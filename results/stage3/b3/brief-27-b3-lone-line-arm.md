## E2. The valid-draw restriction, opt-in ($0)

The restriction is **active only when a valid-draws file is passed** (brief 26's JSON: `items[].draws.valid_by_day` per item and `items[].lone_lines[].valid_draws` per lone line, keyed by opaque id, or a later file of the same shape); in default mode the module draws as before, which is what E1's replay relies on. **S1 and S3 always pass the file.** In restricted mode the module (i) takes every seeded draw for an item or a lone line from that item's listed valid (day, author) pairs; (ii) checks, at the drawn state, that each line's target position is found exactly once, that the document after application equals the intended result and that the line is not already present; and (iii) refuses a draw that fails any check, instead of returning a delivered or last layout (brief 26 names the return at line 567). *Refusal means:* a single draw outside the valid set, or failing a check, is refused; an **item-level selection** of Part S's pair (two valid position draws on different days by different authors, A6.17.11) is refused for an item that cannot supply the pair, even if it has single valid draws (3 of the 8 dropped items have valid draws on one day only). Tests: a draw outside the valid set is refused; a non-unique target is refused; each of the 8 items brief 26 dropped is refused at the pair selection; each of the nine stratum members with `anchors_resolve` false is accepted on both days; and, in restricted mode, a draw that is already valid in default mode yields the identical document and record as default mode.
